# Signal 1.1.0

Signal `1.1.0` adds the opt-in asset and image publishing pipeline to the
stable 1.x engine. Content, configuration, and templates remain compatible
with `1.0.0`; sites that do not configure the new tables keep their existing
page output, while their manifests are refreshed for the new release and
generation identities.

## What's in this release

- **First-class asset inputs.** Static files referenced by entries are
  recorded as declared build inputs. Changing a source asset invalidates the
  pages that embed it without forcing unrelated artifacts to rebuild.
- **Deterministic image derivatives.** `[images]` generates aspect-preserving,
  never-upscaled WebP and AVIF derivatives for content-referenced PNG/JPEG
  sources. Derivatives are planned artifacts with their own reuse and
  pruning decisions.
- **Responsive image markup.** Configured derivatives are exposed through
  `srcset`, `sizes`, and intrinsic dimensions. Multiple formats render
  AVIF-first `<picture>` elements with a WebP fallback; front-matter heroes
  are available as `responsive_image`.
- **Generated social cards.** `[social]` produces deterministic per-entry PNG
  sharing cards with optional hero compositing and Open Graph/Twitter
  metadata. Social cards are first-class incremental-build artifacts and
  require an absolute `site.base_url`.
- **Asset and image diagnostics.** `signal check` and `signal explain`
  report advisory, evidence-based findings for unreferenced raster assets,
  oversized sources, clamped widths, and missing or empty alternative text.
  Diagnostics never write, prune, or fail a build.
- **Expanded build observability.** `signal explain` can describe source
  assets, image derivatives, generated social cards, the search index, and
  other planned artifacts, including their inputs and reuse/rebuild reason.
- **Search and related-content hardening.** The existing search-index and
  related-entry projections now have explicit architecture records and
  regression guardrails for their contracts and incremental inputs.
- **Release packaging.** The release workflow publishes native Linux glibc,
  static Linux musl, macOS Intel, macOS Apple Silicon, and Windows binaries
  with checksums.

## Upgrade notes

Existing site configuration and content need no migration. The `1.1.0`
package version changes the manifest's engine identity, and the image/social
features advance the generation behavior identity to `13`, so the first
build after upgrading performs a full rebuild. Subsequent builds are
incremental again.

The new behavior is opt-in:

```toml
[images]
widths = [640, 1280, 1920]
formats = ["avif", "webp"]

[social]
width = 1200
height = 630
```

Without `[images]` or `[social]`, no derivatives or social cards are
planned.

## Not in this release

Image cropping and art direction, pagination, aliases/redirects, plugins,
CMS integration, alternate social-card themes, a built-in search UI, CSS/JS
bundling, and external crawling remain deliberately deferred.

## Compatibility

Signal remains a deterministic static site generator with no network or
runtime server behavior. `build`, `check`, `serve`, and `explain` continue to
share the same validation and planning pipeline. The 1.1 release preserves
1.x site configuration and CLI compatibility while extending the build
manifest with explicit asset and generated-image inputs.
