# Signal 0.2.0

Signal `0.2.0` is the first release of the complete engine: deterministic
static-site compilation with incremental builds, hardened output handling,
and the full set of generation capabilities exercised by a real-world
reference site.

## What's in this release

- **Deterministic compilation.** Discovery, ordering, routes, generated
  data, and manifests are stable: two clean builds of the same site
  produce byte-identical output, including the build manifest.
- **Incremental builds.** A schema-versioned manifest records per-artifact
  input digests (source content, configuration, template set, consumed
  query projections, output bytes). Unchanged artifacts are reused;
  stale outputs are pruned as *previous manifest − current plan*.
  Mtiles are never consulted; reuse is a total digest predicate.
  - Content, template-set, and configuration invalidation
  - Related-entry, taxonomy, feed, sitemap, and search-index invalidation
  - Git-derived metadata invalidation
- **Markdown and front matter.** CommonMark via Comrak with YAML (`---`)
  and TOML (`+++`) front matter, heading anchors and TOC data, fenced-code
  highlighting with copy affordance, Mermaid blocks, GitHub-style alerts,
  deterministic plain-text extraction. Author raw HTML in content is
  removed, never passed through.
- **Templates.** MiniJinja with HTML auto-escaping, inheritance and
  includes, explicit per-artifact contexts, and a fixed set of engine
  filters/helpers.
- **Taxonomies.** Topic index and per-term pages with canonical ordering.
- **RSS 2.0.** Main feed, per-section feeds, taxonomy label-index and
  per-term feeds, built from the model (never from rendered HTML).
- **Sitemap and robots.txt.** Derived from the explicit public route
  inventory; no fabricated timestamps.
- **Search index.** Versioned JSON schema generated from the normalized
  model (title, description, tags, date, URL, plain text).
- **Git-derived metadata.** Opt-in `[git] last_modified`: entry
  last-modification dates from commit history; advisory on every failure
  mode (missing binary, non-repository, failing query) and always
  overridden by explicit front matter.
- **Related entries.** Deterministic tag-overlap ranking with recency
  tie-breaks, fully invalidated when entries change.
- **404.** A themed not-found page.
- **HTML output minification.** Opt-in `[output] minify_html`:
  deterministic, HTML-aware whitespace reduction that preserves
  `pre`/`code`, Mermaid, `textarea`, scripts, styles, JSON-LD, entities,
  attributes, and comments. Applied to template-rendered HTML only.
- **Hardened filesystem handling.** Lexical path containment, symlink
  refusal at output boundaries, alias-aware collision detection,
  fail-closed source discovery, atomic manifest replacement, and
  fail-safe stale pruning.
- **Safety policy.** `#![forbid(unsafe_code)]` is enforced at every crate
  root; the engine performs no network access and templates have no
  filesystem or network reach.

## Not in this release

- **No CSS/asset pipeline.** Signal copies `static/` verbatim. There is no
  stylesheet concatenation, minification, fingerprinting, or integrity
  attribute generation. Sites that need a build step for CSS/JS must run
  it as an external site/deployment concern and place its results in
  `static/`.

## Compatibility

Signal is a general-purpose static site generator. Its engine-level
behavior has been validated by rebuilding the maintainer's existing
reference site (a Hugo site) with equivalent routes, visible content,
metadata, feeds, assets, and responsive presentation — see
[the compatibility documentation](../compatibility/blog.md). This
demonstrates the generator on a real site; it is not a claim of general
Hugo compatibility, and Hugo features that are not exercised by real
content are deliberately not implemented.

## Upgrading from 0.1.0-beta.1

Configuration and templates are compatible. The build-behavior version
bumped, so the first build after upgrading performs a full rebuild and
subsequent builds are incremental again. See
[Configuration](../configuration.md) for currently supported options,
including the new `[output]` table.
