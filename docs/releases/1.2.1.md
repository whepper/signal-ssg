# Signal 1.2.1

Signal `1.2.1` extends the existing responsive-image pipeline to the actual
homepage featured entry.

## What's in this release

- **Responsive homepage heroes.** The homepage's `featured` summary may now
  carry `featured.responsive_image`, with the same `src`, `srcset`, `sizes`,
  dimensions, alternative text, format-grouped `sources`, and `has_picture`
  fields already available to entry-page templates.
- **Plain-image fallback.** `featured.image` and `featured.image_alt` remain
  unchanged and are used when responsive metadata is unavailable, including
  disabled image pipelines and external or non-raster heroes.
- **Incremental dependency coverage.** A derivable homepage hero makes
  `index.html` declare the selected entry, its source asset, and every
  consumed derivative. Source, format, and featured-selection changes rebuild
  the homepage and relevant artifacts; unchanged derivatives and pages still
  reuse.
- **Shared image behavior.** Entry and homepage heroes use the existing
  `responsive_hero()` implementation, preserving AVIF-first `<picture>` output,
  WebP fallback behavior, single-format responsive `<img>` output, actual
  clamped candidate widths, configured `sizes`, and empty alt fallback.

## Upgrade notes

The workspace package version is `1.2.1`. Existing site configuration,
content, templates, and entry-page contexts remain compatible. The generation
behavior identity advances from `14` to `15` because the homepage can expose
new context data and dependency records. The first build after upgrading may
perform the existing generation-gated rebuild; subsequent builds are
incremental again.

No template filename convention or hardcoded derivative path is required.
Templates should continue to use `featured.responsive_image` and fall back to
`featured.image`.

## Compatibility

The release retains the existing `build`, `check`, `serve`, `explain`, and
`inspect` validation boundary. The manifest schema and artifact kinds are
unchanged. Other listing, feed, related-entry, and taxonomy summaries remain
query projections and do not gain responsive metadata.
