# Signal 1.2.0

Signal `1.2.0` adds bounded page inspection and extends the existing image
derivative pipeline with WebP sources.

## What's in this release

- **Bounded page inspection.** `signal inspect --root <site-root> --format json
  <page>` provides the public `signal.inspect/v1` schema. It is a
  deterministic, page-scoped, machine-readable view of Signal's validated
  understanding of one published page.
- **Resolved page context.** Inspection exposes stable source identity,
  collection, route, URL and canonical URL, publication state, effective
  metadata, headings and fragment IDs, outbound and inbound links, source
  assets, related entries, and page-scoped diagnostics. Collections are bounded
  and report their totals and truncation state.
- **WebP derivative sources.** Content-referenced derivative sources now include
  PNG, JPEG/JPG, and WebP. Configured derivative outputs remain WebP and AVIF;
  AVIF remains an output format rather than a derivative input.
- **Existing image architecture retained.** WebP references use the existing
  derivative, responsive-image, dependency, manifest, and rebuild paths. The
  image behavior version advances from `13` to `14`; the manifest schema and
  artifact kinds are unchanged.

Inspection is read-only, page-scoped, and bounded. It is not arbitrary
filesystem browsing, a full-site content dump, a body or plain-text export, a
network-fetching interface, a mutation or deployment API, an editorial quality
score, a semantic-search or embeddings system, or an MCP implementation.
Drafts and other sources excluded from the published model are not available
through inspection.

## Upgrade notes

The workspace package version is `1.2.0`. Existing site configuration and the
canonical build model remain in use. The generation behavior identity is `14`
because configured WebP sources can introduce derivative artifacts, dependency
inputs, and responsive output; the first compatible build after the behavior
change may perform a rebuild according to the existing manifest gate.

## Not in this release

Body excerpts, whole-site inspection responses, arbitrary file access,
mutation, publishing, deployment, commit operations, semantic search,
embeddings, LLM calls, quality scoring, and an MCP server remain deliberately
deferred.

## Compatibility

The release retains the existing `build`, `check`, `serve`, `explain`, and
`inspect` validation boundary. The manifest schema, artifact kinds, and
existing derivative architecture are unchanged; WebP is added as a source
format while WebP and AVIF remain the configured output formats.
